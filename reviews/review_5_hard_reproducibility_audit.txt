# Audit iteration 2 — deeper C2ST problem: you are not testing the conditional distribution

This one is more fundamental.

Your scientific target is explicitly

\(p_\theta(Y\mid p^\mu,G)\approx p_{\mathrm{G4}}(Y\mid p^\mu,G)\). 

But your C2ST inputs are:

* high level: nine **shower** variables;
* low level: the 6,790 deposited energies;
* profile aware: 65 layer energies.

There are **no incident-condition variables in any of them.** 

Therefore these classifiers principally test the bank-marginalized distribution

\(p(Y)=\int p(Y\mid c)p_{\mathrm{bank}}(c)\,dc\),

not the full conditional law.

This matters because conditional errors can cancel. Your own Figure 3 demonstrates exactly that: V3-SUP goes from roughly \(-6.4\%\) bias in one energy bin to \(+6.4\%\) immediately in the next.  A marginal test can partially wash out such errors.

### Much better C2ST

Give the classifier **both condition and shower observables**:

\(X=(c,Y_{\rm features})\).

Then you compare

\(P_{\rm G4}(c,Y)=P(c)P_{\rm G4}(Y\mid c)\)

against

\(P_{\rm gen}(c,Y)=P(c)P_{\rm gen}(Y\mid c)\).

Because the exact same condition distribution appears in both classes, any separation beyond condition-only discrimination comes from the conditional relationship.

That produces a beautifully coherent evaluation:

**Condition only:** AUROC = 0.5 sanity check.
**Condition + high-level shower:** conditional high-level discrepancy.
**Condition + layer profile:** conditional longitudinal discrepancy.
**Condition + channel vector:** conditional low-level discrepancy.

And all four use **pair-grouped folds**.

That should replace the current Fig. 2.

# Audit iteration 5 — Eq. (4) is not the model you actually sample

This is a real mathematical inconsistency.

Eq. (4) says:

\(V\sim p(V\mid c)\)

then

\(T\sim p(T\mid V,c)\),

with \(V\) representing nonzero deposited response. 

But §4.1 says that when \(V=1\), you sample Gaussian-mixture \(z\), and if \(z<0\),

\(T=s_T\operatorname{expm1}(z)<0\),

so you clamp \(T\) to zero **and then reset \(V=0\)**. 

Thus \(V\) is not simply the variable first sampled from the Bernoulli factor. Its final value also depends on the response-head draw.

The actual effective zero probability is approximately

\(P(T=0\mid c)=P(B=0\mid c)+P(B=1\mid c)P(z\le0\mid B=1,c)\),

where \(B\) is the original hurdle draw.

So either:

### Revision A — fix the notation

Call the first variable \(B\), the hurdle indicator.

Then define the final visibility indicator

\(V=B\,\mathbf 1[T_{\rm raw}>0]\).

But that makes explicit that you have **two zero mechanisms**, which probably isn't what you want.

### Revision B — much better model fix

Make the positive branch strictly positive by construction.

For example:

\(T=s_T\exp z\),

or another invertible positive-support transform.

Then the hurdle is the **only zero atom**.

That makes the factorization truthful and gives much cleaner diagnostics.

A Gaussian fitted to positive \(z=\log(1+T/s_T)\) data necessarily having a negative tail is an avoidable structural flaw. I would fix this even if its empirical zero-mass contribution is small.

# Audit iteration 8 — your CLR flow has a redundant degree of freedom

There is another mathematical issue with §4.2.

A centered log-ratio vector satisfies

\(\sum_{i\in A}x_i=0\).

So the target occupies a \((|A|-1)\)-dimensional subspace.

But you say the source is **masked Gaussian noise**, apparently not centered. 

That means the flow unnecessarily models the additive “all-ones” direction even though softmax later annihilates that direction because

\(\operatorname{softmax}(x+a\mathbf 1)=\operatorname{softmax}(x)\).

Nothing is necessarily mathematically invalid, but it is redundant and potentially badly conditioned.

### Better

Center the source too:

\(x_0=\epsilon-\bar\epsilon_A\mathbf1\),

on the active coordinates.

Or use an **ILR basis**, giving an actual \(|A|-1\)-dimensional unconstrained Euclidean representation.

The CLR/softmax relationship itself is standard compositional-data machinery. ([OUP Academic][2])

I would at least run centered-source Gaussian vs current source as a cheap ablation.

# Audit iteration 11 — Gumbel-Top-k may be structurally bad at generating clustered support

Your support model produces node scores and then selects exactly \(K_\ell\) channels with one Gumbel-Top-k draw. 

This gives an exact-size random subset, which is elegant.

But think about the generative structure: the \(K\) selected cells are not chosen through a process in which selecting cell \(i\) changes the probabilities of its neighbors because it has become part of the shower. They primarily compete through static/event-conditioned scores plus without-replacement sampling.

That is a potentially weak mechanism for a spatially correlated shower.

Your support scorer can learn a contiguous high-score region, so it is not hopeless. But the sampled set has no explicit **selection-dependent topology**.

That could contribute directly to the huge connected-component count.

### Strong diagnostic

Evaluate support using **oracle**:

* true active layers;
* true per-layer energy;
* true per-layer \(K_\ell\).

Then sample only \(H_\ell\).

If connected components remain terrible, you have isolated the support mechanism.

If they become reasonable, the fragmentation is mainly propagated from upstream variables.

### Architectural alternatives if support really is the problem

A graph-autoregressive growth process is particularly natural:

1. sample one or several shower seeds;
2. repeatedly add nodes conditioned on the currently selected support;
3. stop at exactly \(K_\ell\).

That directly encodes local clustering while retaining exact cardinality.

Other possibilities include correlated subset models, latent shower-core models, or cluster-then-sample approaches.
